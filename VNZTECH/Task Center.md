## How to use

- One record per substantive logical request. Simple read-only questions use [[90 System/Tasks/Quick Requests]]; promote one when scope grows.

- Track planning → awaiting_approval → approved → in_progress → implemented/verified → ready_for_review → accepted/completed. Paused, blocked, cancelled, and needs_triage stay explicit. Implementation approval is not result acceptance.

- Save milestone/handoff checkpoints and preserve old tasks when updating the current pointer. Record actual writer/runner and reconcile before ownership changes; markers are advisory.

- This is instruction-driven task memory for runners using the same accessible/synchronized workspace; it does not watch arbitrary manual edits or start AI tasks in the background.
